# Task 9 — Front-end Technical Specification: Theme Documentation

## 1. Objective

Create a new `/docs` file dedicated to the `@cobranza-apps/ui` theme (tokens, import paths, utility classes) and link it from `README.md`. Ensure every SCSS partial under `src/lib/theme/` has a brief top-level comment.

## 2. Source of Truth

- `README.md` — library entry point; its "Documentation" section already links to `/docs/USAGE.md` and project-info files.
- `docs/USAGE.md` — contains a `Theme Import` section and a `Design Tokens Reference` section.
- `.agent/project-info/brief.md` §5 — authoritative design tokens and token groups.
- `src/lib/theme/*.scss` — implementation source.

## 3. Existing Docs Assessment

- `README.md` has a `Design Tokens (Theme)` section with a summary of token groups, prefix, utility-class examples, and a link to `brief.md §5` and `src/lib/theme/`.
- `README.md` has a `Documentation` section listing `/docs/USAGE.md`, project-info files, and JSDoc.
- `docs/USAGE.md` has a `Theme Import` section and a `Design Tokens Reference` section with usage examples.
- Neither file has a dedicated, concise theme reference document.

## 4. New Doc File Specification

### 4.1 Path

`docs/THEME.md`

### 4.2 Link Placement

Add a new entry in `README.md` → `Documentation` section:

```markdown
- [`/docs/THEME.md`](/docs/THEME.md) — Theme import, tokens, and utility classes.
```

Also add a brief cross-reference in `README.md` → `Design Tokens (Theme)` section, pointing to the new file for a quick reference:

```markdown
For a quick reference, see [`/docs/THEME.md`](/docs/THEME.md).
```

### 4.3 Content Structure

`docs/THEME.md` must contain the following sections in order:

1. **AI Agent Note** (comment at top of file) — state that this file is the quick reference for the theme and that authoritative token values live in `brief.md §5` and `src/lib/theme/`.
2. **Title** — `# @cobranza-apps/ui — Theme Reference`
3. **Table of Contents** — list all sections below.
4. **Importing the Theme** — document both the SCSS `@use` import and the CSS-only `@import` path.
   - Include the exact import paths.
   - Mention `bootstrap` (CSS-only) is a peer dependency.
   - Mention that the theme emits `--cba-*` CSS variables on `:root` and opt-in `.cba-*` utility classes.
5. **Token Prefix** — explicitly state that all CSS variables use the `--cba-` prefix.
6. **Main Token Groups** — reproduce the token groups from `brief.md §5` (with example variables, not necessarily every value) organized by:
   - Backgrounds
   - Text
   - Borders
   - Accents
   - Interactive states
   - Layout constants
   - Radius
   - Shadows
   - Spacing scale
   - Typography
7. **Utility Class Prefix** — explicitly state that all utility classes use the `.cba-` prefix.
   - List the main utility classes generated by `_utilities.scss`:
     - Background utilities: `.cba-bg-primary`, `.cba-bg-secondary`, `.cba-bg-tertiary`, `.cba-bg-elevated`
     - Text utilities: `.cba-text-primary`, `.cba-text-secondary`, `.cba-text-muted`, `.cba-text-inverse`
     - Border utilities: `.cba-border-subtle`, `.cba-border-default`, `.cba-border-strong`
     - Radius utilities: `.cba-radius-sm`, `.cba-radius-md`, `.cba-radius-lg`
     - Shadow utilities: `.cba-shadow-module`, `.cba-shadow-elevated`
     - Spacing utilities: `.cba-p-*`, `.cba-m-*` for scales 1–8
   - Note that border utilities control `border-color`; they may need to be paired with Bootstrap's `.border` / `.border-1`.
8. **Mixins** — optional quick reference to `src/lib/theme/_mixins.scss` and how to use the `cba-focus-ring`, `cba-elevated-surface`, and `cba-hover-surface` mixins.
9. **Cross-References** — links to:
   - `README.md`
   - `docs/USAGE.md`
   - `.agent/project-info/brief.md` §5
   - `src/lib/theme/` source files

### 4.4 Constraints

- No new unit tests for pure SCSS tokens.
- Keep stylelint green if it exists.
- Do not duplicate authoritative token values; reference `brief.md §5` and `src/lib/theme/`.
- The doc should be a quick reference, not a replacement for `USAGE.md` or `brief.md`.
