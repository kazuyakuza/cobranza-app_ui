## Findings

`ModuleHeaderComponent` works correctly, but its TypeScript class keeps several fine-grained computed signals and an umbrella `aria` object that can be collapsed into fewer, more cohesive members. The `statusClass` computed also carries a `null` value that forces a template fallback.

`module-header.component.spec.ts`, `demo-module-card.component.ts`, `docs/CBA_MODULE_HEADER.md`, and `CHANGELOG.md` do **not** require simplification changes.

## Simplifications

### S1. Replace umbrella `aria` object with focused properties

The `protected readonly aria` object is used only to read four leaf strings. Split it into four `protected readonly` properties so the template and computed signals access the exact value they need without `aria.*` indirection.

### S2. Group collapse button state

Merge `collapseLabel` and `collapseIcon` into one `collapseButton` computed signal that returns `{ label, icon }`. This reduces class members and keeps the two collapse-button visuals together.

### S3. Group size-toggle button state

Merge `sizeToggleLabel`, `sizeToggleIcon`, and `sizeToggleTarget` into one `sizeToggleButton` computed signal that returns `{ label, icon, target }`. Same rationale as S2.

### S4. Return `''` from `statusClass` instead of `null`

The status section binding is `[class]="statusClass() ?? ''"`. If `statusClass` returns `''` directly, the `?? ''` fallback becomes unnecessary and the template is simpler.

### S5. Remove dead `?? null` fallback in `statusVisual`

`STATUS_VISUALS` is typed as `Record<Exclude<ModuleHeaderStatus, null>, StatusVisual>`, so every non-null status has a mapping. The `STATUS_VISUALS[current] ?? null` fallback can never execute and should be removed.

## Implementation steps

### Step 1 — `src/components/module-header/module-header.component.ts`

1. Remove the `protected readonly aria` property.
2. Add four focused aria properties:

```ts
  /** Aria label for the fullscreen button. */
  protected readonly ariaFullscreen = CBA_UI_MESSAGES.moduleHeader.aria.fullscreen;

  /** Aria label for the remove button. */
  protected readonly ariaRemove = CBA_UI_MESSAGES.moduleHeader.aria.remove;

  /** Collapse/expand button aria labels. */
  protected readonly ariaCollapse = CBA_UI_MESSAGES.moduleHeader.aria.collapse;

  /** Size-toggle button aria labels. */
  protected readonly ariaSize = CBA_UI_MESSAGES.moduleHeader.aria.size;
```

3. Replace `collapseLabel` and `collapseIcon` with:

```ts
  /** Collapse/expand button state (label + icon). */
  protected readonly collapseButton = computed<{ label: string; icon: IconDefinition }>(() =>
    this.isCollapsed()
      ? { label: this.ariaCollapse.expand, icon: faChevronDown }
      : { label: this.ariaCollapse.collapse, icon: faChevronUp },
  );
```

4. Replace `sizeToggleLabel`, `sizeToggleIcon`, and `sizeToggleTarget` with:

```ts
  /** Size-toggle button state (label + icon + target size). */
  protected readonly sizeToggleButton = computed<{
    label: string;
    icon: IconDefinition;
    target: ModuleHeaderSize;
  }>(() =>
    this.isFullSize()
      ? { label: this.ariaSize.shrink, icon: faArrowsLeftRightToLine, target: '50%' }
      : { label: this.ariaSize.expand, icon: faArrowsLeftRight, target: '100%' },
  );
```

5. Update `statusClass` to return `''` instead of `null`:

```ts
  /** CSS modifier class for the status section, or an empty string when no status is set. */
  readonly statusClass = computed<string>(() => {
    const current = this.status();
    return current === null ? '' : `cba-module-header__status--${current}`;
  });
```

6. Update `statusVisual` to remove the dead fallback:

```ts
  /** Status visual config or `null` when no status is set (icon hidden). */
  readonly statusVisual = computed<StatusVisual | null>(() => {
    const current = this.status();
    return current === null ? null : STATUS_VISUALS[current];
  });
```
