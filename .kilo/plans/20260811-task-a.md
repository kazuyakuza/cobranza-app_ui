**Technical decisions (with rationale):**

1. **Test strategy — host class contract only in jsdom.**
   The existing `module-container.component.spec.ts` (line 61) explicitly documents that "CSS chrome suppression is not testable in jsdom; the host modifier is the contract." `jest-environment-jsdom` does not compute real layout values for `overscroll-behavior`, `aspect-ratio`, `background-color`, `display`, `width`, `justify-content`, or `box-shadow`. New tests **mirror this established convention**: assert presence/absence of the host modifier class. Computed-style expectations from the front-end spec are documented inside the test file as comments (Cannot-compute-in-jsdom notes) so the contract is recorded without producing flaky/failing assertions. This resolves the ambiguity between the spec's "computed style" expectations and the jsdom limitation without deviating from existing project practice.

2. **Version header `0.14.0`.**
   `package.json` already declares `"version": "0.14.0"` but `CHANGELOG.md` has no `## [0.14.0]` header (latest is `0.13.0 — 2026-08-09`). Per `.kilo/rules/changelog-versioning.md`, the same commit that introduces the change must add the dated header. Plan adds `## [0.14.0] — 2026-08-11` directly above `## [0.13.0]`. No `[Unreleased]` section is created. Minor bump is correct: all changes are additive (new inputs) + one visual fix; no breaking API change.

3. **No new public types.** All new inputs are `boolean` primitives; no new type files. Existing `CbaButtonVariant` / `CbaButtonSize` and `ModuleContainerSize` / `ModuleContainerPadding` are untouched.

4. **SCSS rule ordering.** New modifier rules are appended at the end of the respective `.scss` files (after the existing size modifiers in the button file, after the padding modifiers in the container file). The fullscreen split (Task 2) is the only edit that touches the existing structure and is done as a refactor of the existing `:host` + `:host(:not(...))` block.

5. **No `::ng-deep` additions.** All new rules use host-class selectors (`:host(.cba-button--truncate)`, `:host(.cba-button--block)`, `:host(.cba-module-container--scroll-chaining)`) or plain descendant selectors on already-encapsulated classes. Aligns with the prohibition that motivated the Shell TODO.

6. **MAX-args rule compliance.** All new inputs are single-argument Angular `input<T>()` signals; no method exceeds 2 args. No file exceeds 200 lines. No method body exceeds 50 lines.

7. **Task 2 doc note on Shell workaround removal.** Per the spec's cross-cutting notes, the Shell `.cba-bg-secondary` workaround becomes harmless once the library retains the background. The plan records this in the changelog Notes section but does **not** modify any Shell files — Shell-side cleanup is out of scope for this library TODO.

Set `[iconOnly]="true"` to render a minimal square button when the button contains only an icon.
