**Result:** OK.

### Imports and exports

- `demo-payment-schedule` imports `CbaBadgeComponent` from `@cobranza-apps/ui`; exported by `src/public-api.ts`.
- `demo-workspace` retains `CbaButtonComponent` and `faDownload` for the untouched "Export data" module, exactly per the plan's contradiction resolution.

**Result:** OK.

### Theme token accuracy

All tokens referenced in the new SCSS files exist in `src/theme/_variables.scss`:

- `--cba-space-1`, `--cba-space-2`, `--cba-space-3`
- `--cba-text-primary`, `--cba-text-secondary`, `--cba-text-muted`, `--cba-text-inverse`

**Result:** OK.

### CSS specificity and encapsulation

- Both new components use `:host { display: block; }` and BEM-style class names scoped to the component (`demo-customer-form*`, `demo-payment-schedule*`, `demo-calendar*`, `demo-payment-list*`).
- No global element overrides; no leakage outside the components.
- No hard-coded colours; the only non-token values are `1px` border widths and `600` font-weight, which are acceptable structural/visual defaults and match the implementation plan.

**Result:** OK.

### Template correctness

- `demo-customer-form` renders three `cba-input` fields with `label`, `type`, and `placeholder` inputs. `CbaInputComponent` supports `type="text"` and `type="email"`, and forwards `label`/`placeholder` to the internal field and native input.
- `demo-customer-form` renders a `cba-button` with `variant="primary"`, `type="button"`, and `[icon]="faPlus"`. `CbaButtonComponent` supports all of these inputs.
- `demo-payment-schedule` renders a 30-day calendar with a selected day 15 and a payment list. The `@for` and `@switch` control-flow syntax is valid for Angular 22.
- `demo-payment-schedule` uses `<cba-badge variant="warning" appearance="outline">` and `<cba-badge variant="success" appearance="outline">`. Both variants and `appearance="outline"` are valid for `CbaBadgeComponent`.
- `demo-workspace.component.html` replaced the "New customer" actions block with `<demo-customer-form />` and the "Payment schedule" paragraph with `<demo-payment-schedule />`.
- The "Export data" module was left untouched, preserving its `<div class="demo-actions">` block.
- Self-closing component tags (`<demo-customer-form />`, `<demo-payment-schedule />`, `<cba-module-header />`, `<cba-module-footer />`) are valid in Angular 22.

**Result:** OK.
