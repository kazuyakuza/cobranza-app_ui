## Fix module container footer placement [DONE]

The `cba-module-footer` is currently rendered inside `cba-module-container__body` because `ModuleContainerComponent` has only one content projection slot and it lives inside the body `<div>`. This causes:

- Footer scrolls with body content instead of staying fixed at the bottom of the module.
- Footer does not look integrated with the module chrome (border-radius, shadow).
- On collapsed modules the footer is still visible because the container only removes the body wrapper via `@if (!isCollapsed())`, but projected content outside the body doesn't exist.

**Required changes:**

1. **Library — `ModuleContainerComponent`**: Add a dedicated footer projection slot `[cbaModuleContainerFooter]` rendered **after** the body div, still inside the `@if (!isCollapsed())` block, so it is removed together with the body when collapsed.
   - Update `module-container.component.html` to add:
     ```html
     <div class="cba-module-container__footer">
       <ng-content select="[cbaModuleContainerFooter]"></ng-content>
     </div>
     ```
   - Update `module-container.component.scss` to style `__footer`:
     - `flex: 0 0 auto`
     - `min-height: 0`
     - No scroll, never shrinks (same as header band semantics).
     - Background `var(--cba-bg-tertiary)` to match footer surface.
     - Border-top `1px solid var(--cba-border-subtle)` to separate from body.
   - Update `docs/CBA_MODULE_CONTAINER.md` to document the new footer slot.

2. **Demo — `demo-module-card.component.ts`**: Change footer placement from generic projected content to the new footer slot:
   ```html
   <cba-module-footer cbaModuleContainerFooter [status]="footerStatus" [statusText]="footerText" />
   ```

3. **Library — `CbaModuleFooterComponent`**: Verify the footer no longer needs its own `background-color` or `height` if the container footer band provides them. Keep the component self-contained for standalone use, but ensure it looks correct when placed inside the container footer slot.

## Fix 50% module width / empty space parity [DONE]

Current `workspace__row--single-50` uses `grid-template-columns: 50% 1fr;`. This makes a single 50% module wider than the empty space beside it. When a row contains one or two 50% modules, the module width and the empty space must be identical.

**Required changes:**

1. **Demo — `demo-workspace.component.scss`**:
   - Change `.workspace__row` to `grid-template-columns: repeat(2, 1fr);` (already correct).
   - Change `.workspace__row--single-50` to `grid-template-columns: repeat(2, 1fr);` as well, so the single module occupies exactly the first half and the empty second half matches it.
   - Ensure `.demo-module-card--size-50 > cba-module-container` has `width: 100%;` (already present; verify).

2. **Demo — `demo-workspace.component.html`**: No structural changes needed if SCSS grid is fixed.
