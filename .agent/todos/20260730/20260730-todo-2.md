# Phase 4 — Core Presentational Components

## Objective

Implement the minimum set of reusable presentational components needed by the Shell and early MFEs:

- `CbaButton`
- `CbaCard`
- `CbaBadge`
- `CbaEmptyState`
- `CbaSkeleton`

At the end of this phase each component must:

- Be standalone
- Use only design tokens from the theme
- Expose a clear, documented API
- Be exported from the public API
- Include JSDoc, usage documentation and real examples.
- Include focused unit tests

## Important constraints

- Desktop-only.
- Keep components thin and presentational — no business logic.
- Prefer composition and content projection over rigid templates.
- All colors, spacing, radii, shadows and focus styles must come from `--cba-*` tokens.
- Visual language: modern, professional, calm, friendly (not rigid corporate).
- Do not introduce new design tokens unless strictly necessary; reuse the existing theme.

### 1. Implement CbaButton Component [DONE]

**Selector:** `cba-button`

#### API

| Kind | Name | Type / values | Default | Notes |
| ------ | ------ | --------------- | --------- | ------- |
| Input | `variant` | `'primary' \| 'secondary' \| 'ghost' \| 'danger' \| 'success'` | `'primary'` | Visual style |
| Input | `size` | `'sm' \| 'md'` | `'md'` | Control size |
| Input | `loading` | `boolean` | `false` | Shows spinner and disables interaction |
| Input | `disabled` | `boolean` | `false` | Standard disabled state |
| Input | `type` | `'button' \| 'submit' \| 'reset'` | `'button'` | Native button type |
| Content | default | projected content | — | Label / inner content |
| Content | optional icon | projected or input-driven | — | Leading/trailing icon support is desirable |

#### Behaviour & visuals

- [ ] Native `<button>` under the hood (keyboard accessible).
- [ ] `loading === true` → show spinner, prevent clicks, keep layout stable.
- [ ] Variants map to accent / surface tokens:
  - `primary` → accent primary
  - `secondary` → subtle elevated / bordered surface
  - `ghost` → transparent with hover surface
  - `danger` → accent danger
  - `success` → accent success
- [ ] Hover / active / focus use `--cba-hover`, `--cba-active`, `--cba-focus-ring`.
- [ ] Sizes affect padding and font-size using spacing tokens.
- [ ] Icon support: either content projection or a simple icon input; keep it lightweight.

#### Docs & tests

- [ ] JSDoc on all public members (AI-agent friendly).
- [ ] Docs section with usage examples for each variant.
- [ ] Minimal tests: renders label, emits click when enabled, does not emit when `loading` or `disabled`.

### 2. Implement CbaCard Component [DONE]

**Selector:** `cba-card`

#### API

| Kind | Name | Notes |
| ------ | ------ | ------- |
| Content | default | Card body |
| Content | header slot | Optional header region |
| Content | footer slot | Optional footer region |

Suggested projection pattern (implementer may choose equivalent clear API):

- `[cbaCardHeader]` / `cba-card-header`
- default content = body
- `[cbaCardFooter]` / `cba-card-footer`

#### Behaviour & visuals

- [ ] Optional header and footer — if not projected, those regions are not rendered.
- [ ] Body always available via default projection.
- [ ] Surface uses elevated / secondary background + subtle border.
- [ ] Radius via `--cba-radius-md` (or equivalent).
- [ ] **No forced hover elevation.**
- [ ] Padding balanced via spacing tokens.

#### Docs & tests

- [ ] JSDoc + usage examples (body only, header+body, header+body+footer).
- [ ] Minimal tests: projects body; renders header/footer only when provided.

### 4. Implement CbaEmptyState Component [DONE]

**Selector:** `cba-empty-state`

#### API

| Kind | Name | Notes |
| ------ | ------ | ------- |
| Input / content | `icon` | Optional icon (projection or input) |
| Input / content | `title` | Required-looking primary message |
| Input / content | `description` | Optional secondary text |
| Content | action slot | Optional primary action (usually a button) |

Exact binding style (inputs vs projection) may be chosen for ergonomics, but the four slots of meaning must exist: icon, title, description, action.

#### Behaviour & visuals

- [ ] Centered, calm layout.
- [ ] Clear hierarchy: icon → title → description → action.
- [ ] Uses muted/secondary text tokens for description.
- [ ] Spacing via `--cba-space-*` so it feels balanced, not sparse or cramped.
- [ ] No heavy illustration system — simple icon is enough.

#### Docs & tests

- [ ] JSDoc + example with icon/title/description/action.
- [ ] Minimal tests: renders title; optional regions appear only when provided.

### 5. Implement CbaSkeleton Component [DONE]

**Selector:** `cba-skeleton`

#### API

| Kind | Name | Type / values | Default | Notes |
| ------ | ------ | --------------- | --------- | ------- |
| Input | `variant` | `'text' \| 'avatar' \| 'card' \| 'table-row' \| 'generic'` | `'generic'` | Preset shape |
| Input | `width` | `string` (e.g. `'100%'`, `'12rem'`) | optional | Override width when useful |
| Input | `height` | `string` | optional | Override height when useful |

#### Variant meaning

| Variant | Intent |
| --------- | -------- |
| `text` | One or more text-line placeholders |
| `avatar` | Circular placeholder |
| `card` | Block placeholder resembling a card surface |
| `table-row` | Multi-cell row placeholder (useful while any table loads, including future `mfe-table`) |
| `generic` | Simple rectangular block |

#### Behaviour & visuals

- [ ] Subtle pulse / shimmer animation using theme colors (no hard-coded grays outside tokens).
- [ ] `table-row` should look like several cells in a horizontal row, not a full table component.
- [ ] Keep API simple; this is a placeholder, not a layout engine.

#### Docs & tests

- [ ] JSDoc + examples for each variant.
- [ ] Minimal tests: default variant renders; `variant` switches expected host/class state.

## Important details for all components

### Structure

- [ ] Place each component under `src/lib/components/<name>/`.
- [ ] Prefer one folder per component with `.ts`, `.html`/inline template, `.scss`, and `.spec.ts` as needed.

### Styling rules

- [ ] Only `--cba-*` tokens for color, spacing, radius, shadow, focus.
- [ ] Reuse theme mixins where helpful (`cba-focus-ring`, etc.).
- [ ] Calm hover/focus interactions.

### Export

- [ ] Export every component from `src/public-api.ts`.
- [ ] Library build must succeed after all five components are added.

### Documentation

- [ ] Create or extend docs under `/docs` (and link from `README.md`) covering:
  - When to use each component
  - API summary
  - Minimal code examples
- [ ] JSDoc must be written so an AI agent can use the components correctly without guessing.

### Tests

- [ ] Keep tests focused and few.
- [ ] Prefer behaviour assertions (render, projection, disabled/loading, variant class) over brittle HTML snapshots.
