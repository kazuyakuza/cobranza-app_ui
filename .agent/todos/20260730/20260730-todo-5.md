# Phase 7 — Accordion, Spanish UI copy & Delivery Polish

## Objective

Close the library for consumption by Shell and MFEs by completing three things:

1. **`CbaAccordion`** — thin wrapper on ng-bootstrap accordion (confirmed needed)
2. **Spanish-only UI copy** — all user-visible default texts in components must be Spanish
3. **Delivery polish** — final public API, package metadata, README/USAGE, export cleanup

At the end of this phase `@cobranza-apps/ui` should be ready to install and use from the Company Back-office Shell and first MFEs.

## Important constraints

- Desktop-only.
- **Not multi-language.** The platform will **not** support i18n / locale switching.
- Therefore: do **not** introduce ngx-translate, `$localize` runtime switching, or a language selector.
- Default user-visible strings must be **Spanish**.
- Prefer a **single centralized defaults file** for built-in component strings so copy stays consistent and easy to maintain — without building a translation system.
- Bootstrap / ng-bootstrap remain the base for accordion behaviour.
- No business logic, no BFF integration.

## Tasks

### 1. Implement CbaAccordion

**Selector:** `cba-accordion` (+ item API as needed)  
**Base:** `@ng-bootstrap/ng-bootstrap` accordion

ng-bootstrap owns expand/collapse behaviour. `CbaAccordion` owns theme styling and a stable consumer API.

#### API (suggested)

Keep it thin and close to ng-bootstrap concepts:

| Kind | Name | Notes |
| ------ | ------ | ------- |
| Container | `cba-accordion` | Wraps one or more items; may expose `closeOthers` or equivalent if thin to pass through |
| Item | `cba-accordion-item` (or documented ng-bootstrap item usage wrapped consistently) | Title + body |
| Content | title / header | Projected or input title |
| Content | body | Projected collapsible content |

Exact structure may follow ng-bootstrap’s standalone accordion API, but the public usage must be documented as `cba-*` and theme-aligned.

#### Behaviour & visuals

- [ ] Build on ng-bootstrap accordion — do not reimplement collapse logic.
- [ ] Header/button surface uses theme tokens (text, hover, border).
- [ ] Expanded/collapsed body uses calm spacing and readable text tokens.
- [ ] Borders/radius aligned with cards/surfaces (`--cba-radius-md`, subtle borders).
- [ ] Place under `src/lib/components/accordion/`.
- [ ] Export from `src/public-api.ts`.
- [ ] Build must succeed.

#### Docs & tests

- [ ] JSDoc + usage example with 2–3 items.
- [ ] Explicit note that behaviour comes from ng-bootstrap.
- [ ] Minimal wrapper tests only.

### 2. Spanish-only UI copy (no multi-language system)

#### Decision (mandatory)

- The product is **Spanish-only**.
- All **default printable / on-screen texts** owned by this library must be in **Spanish**.
- Do **not** implement multi-locale infrastructure.

#### Recommended approach

Create a small centralized defaults module, for example:

```ts
// src/lib/i18n/ui-messages.ts  (name may vary)
export const CBA_UI_MESSAGES = {
  moduleFooter: {
    loading: 'Cargando…',
    loaded: 'Listo',
    success: 'Guardado',
    warning: 'Requiere atención',
    error: 'Error',
    dirty: 'Cambios sin guardar',
  },
  // other component defaults…
} as const;
```

Rules:

- [ ] Centralize **library-owned default strings** in one place (constants object).
- [ ] Components read defaults from that module.
- [ ] Consumers may still override texts via inputs (`statusText`, `title`, projected content, etc.).
- [ ] Do **not** add language codes, locale switchers, or translation loaders.

#### Scope of texts to review / fix

Audit every component already implemented in Phases 2–6 and update defaults to Spanish where the library itself provides copy, including at least:

- [ ] `CbaModuleFooter` default status texts
- [ ] Any default button labels the library might expose
- [ ] Empty-state default fallbacks if the component provides any
- [ ] Aria-labels / `title` tooltips on icon-only controls in `ModuleHeader` and similar  
  (these are user-facing via screen readers / hover; use clear Spanish)
- [ ] Any modal dismiss/close labels owned by the library
- [ ] Skeleton / placeholder text only if such text exists (usually none)

**Not in scope for translation infrastructure:**

- Content projected by Shell/MFEs (titles, business labels, form option texts) — that content is provided by consumers and is expected to already be Spanish at the product level.

#### Docs

- [ ] Document in README/USAGE:
  - Platform is Spanish-only
  - Library default chrome strings are Spanish
  - Overrides are done via inputs/projection, not via an i18n framework

#### Tests

- [ ] Where defaults matter (e.g. module footer status text), assert the Spanish default string.
- [ ] No i18n framework tests.

### 3. Public API finalization

## Acceptance criteria

Phase 7 is complete when all of the following are true:

| # | Criterion |
| --- | ----------- |
| 1 | `CbaAccordion` exists as a thin ng-bootstrap accordion wrapper and compiles. |
| 2 | Library-owned default on-screen strings are Spanish. |
| 3 | Defaults are centralized in one constants module (no multi-language framework). |
| 4 | ModuleHeader aria-labels/tooltips and ModuleFooter status defaults are Spanish. |
| 5 | `public-api.ts` exports only the intended stable surface. |
| 6 | Package metadata and build output are correct for local consumption. |
| 7 | README + docs index/examples are complete enough for Shell/MFE/AI usage. |
| 8 | Library build succeeds and leftover scaffold/demo code is removed. |

## Explicitly out of scope for Phase 7

- Multi-language / locale switching
- ngx-translate / runtime i18n catalogs
- New major components beyond Accordion
- npm publish automation / CI release pipeline (unless already present and trivial)
- Storybook
- Advanced accordion features not provided by ng-bootstrap
