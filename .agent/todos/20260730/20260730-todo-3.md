# Phase 5 — Modal & Form Control Wrappers

## Objective

Implement thin wrappers around **Bootstrap 5 + ng-bootstrap** for the most common overlay and form needs:

- `CbaModal` — thin Angular wrapper on top of ng-bootstrap modal
- `CbaInput` — theme-aligned text input field
- `CbaSelect` — theme-aligned select field
- `CbaDatepicker` — thin wrapper around ng-bootstrap datepicker

At the end of this phase the library must offer a clear, documented way for Shell and MFEs to open modals and render consistent form controls styled with the intermediate gray theme.

## Important constraints

- Desktop-only.
- **Bootstrap / ng-bootstrap are the base.** Do not reimplement modal, datepicker behaviour, focus trap, backdrop, or calendar logic from scratch.
- Wrappers must stay thin: encapsulate API + theme styling + content projection, nothing more.
- No business logic, validation engine, or BFF integration.
- All visual styling must use `--cba-*` tokens.
- Components must be standalone.
- Keep APIs small and AI-agent friendly.

## Tasks

### 1. Implement CbaModal (wrapper on ng-bootstrap) [DONE]

**Selector:** `cba-modal`  
**Base:** `@ng-bootstrap/ng-bootstrap` modal primitives (`NgbModal`, modal ref, etc.)

This is a **thin Angular wrapper on top of ng-bootstrap**, not a custom modal system. ng-bootstrap owns behaviour (open/close, backdrop, ESC, focus management). `CbaModal` owns consistent structure, theme chrome, and a stable consumer API.

#### API (suggested)

| Kind | Name | Type / values | Default | Notes |
| ------ | ------ | --------------- | --------- | ------- |
| Input | `title` | `string` | optional | Optional convenience title |
| Input | `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Maps to ng-bootstrap / Bootstrap size |
| Input | `centered` | `boolean` | `false` | Vertically centered modal |
| Input | `dismissible` | `boolean` | `true` | Backdrop click / ESC dismiss |
| Content | header slot | projected | — | Optional custom header |
| Content | default / body | projected | — | Modal body |
| Content | footer slot | projected | — | Actions (typically `cba-button`) |

Open/close ergonomics may use ng-bootstrap’s standard service/ref pattern. Document the exact consumer usage clearly (how to open from a parent component, how to dismiss, how to pass data if needed).

#### Behaviour & visuals

- [x] Build on ng-bootstrap modal — do **not** reinvent backdrop, focus trap, or dismiss logic.
- [x] Modal surface uses elevated background + subtle border tokens.
- [x] Radius via `--cba-radius-md` / `--cba-radius-lg`.
- [x] Overlay/backdrop aligned with `--cba-bg-overlay` where practical.
- [x] Title uses primary text token; body keeps clear readable hierarchy.
- [x] Footer actions should work naturally with `cba-button`.
- [x] Place under `src/lib/components/modal/`.
- [x] Export from `src/public-api.ts`.
- [x] Library must still build successfully after adding the component.

#### Docs & tests

- [x] JSDoc on the public API (AI-agent friendly).
- [x] Docs section covering:
  - How to open / dismiss the modal
  - Projection example (header/body/footer)
  - Size options
  - Explicit note that behaviour comes from ng-bootstrap
- [x] Minimal tests only for real wrapper logic (projected regions, size mapping, etc.). Do not re-test ng-bootstrap internals.

### 2. Implement shared form-field structure (internal)

Before the individual controls, define a consistent field layout reused by input/select/datepicker:

- Label
- Control
- Hint / helper text
- Error text (visual only; no validation framework)

#### Visual rules

- [ ] Field background: subtle surface (`--cba-bg-secondary` / `--cba-bg-tertiary`)
- [ ] Border: `--cba-border-default` (stronger on focus if useful)
- [ ] Placeholder / muted text: `--cba-text-muted`
- [ ] Error text: `--cba-accent-danger`
- [ ] Focus styles: `--cba-focus-ring`
- [ ] Spacing between label / control / hint / error via `--cba-space-*`

This may be an internal shared component, partial template, or SCSS structure. It does not need to be public if the public units are `cba-input`, `cba-select`, `cba-datepicker`.

- [ ] Document the label / hint / error conventions in `/docs` so all form controls stay consistent.

### 5. Implement CbaDatepicker

**Selector:** `cba-datepicker`  
**Base:** `@ng-bootstrap/ng-bootstrap` datepicker

This is a **thin wrapper** around ng-bootstrap datepicker. ng-bootstrap owns calendar popup, keyboard interaction and date handling. `CbaDatepicker` owns field structure + theme alignment + stable API.

#### API (suggested)

| Kind | Name | Notes |
| ------ | ------ | ------- |
| Input | `label` | Visible label |
| Input | `disabled` | Disabled state |
| Input | `hint` | Optional helper text |
| Input | `error` | Optional error message (visual only) |
| Input | `placeholder` | Optional |
| Control value | forms compatibility | Prefer Angular forms-friendly binding if feasible |

#### Behaviour & visuals

- [ ] Reuse the shared form-field structure.
- [ ] Rely on ng-bootstrap for popup/calendar behaviour.
- [ ] Theme the input surface with the same tokens as input/select.
- [ ] Theme the calendar popup with elevated surface tokens where practical, without rewriting ng-bootstrap internals.
- [ ] Place under `src/lib/components/datepicker/` (or shared form folder).
- [ ] Export from `src/public-api.ts`.
- [ ] Build must succeed.

#### Docs & tests

- [ ] JSDoc + usage example.
- [ ] Explicit note in docs that calendar behaviour comes from ng-bootstrap.

## Acceptance criteria

Phase 5 is complete when all of the following are true:

| # | Criterion |
| --- | ----------- |
| 1 | `CbaModal` exists as a thin wrapper on ng-bootstrap modal and compiles. |
| 2 | `CbaInput`, `CbaSelect`, and `CbaDatepicker` exist and compile. |
| 3 | Modal behaviour is delegated to ng-bootstrap (no custom modal engine). |
| 4 | Datepicker behaviour is delegated to ng-bootstrap datepicker. |
| 5 | Input/select/datepicker share consistent label / hint / error field structure. |
| 6 | Visuals use only theme tokens and fit the intermediate gray system. |
| 7 | All implemented components are exported from `public-api.ts`. |
| 8 | Library build succeeds. |
| 9 | Docs + minimal tests appropriate to each wrapper are present. |

## Explicitly out of scope for Phase 5

- Custom modal system not based on ng-bootstrap
- Full form validation framework / schema-based forms
- Complex multi-step wizards
- Custom advanced select (virtual scroll, multi-select tagging, async search UI)
- File upload controls
- Toast / notification system
- Tables
- Anything requiring BFF or business rules
