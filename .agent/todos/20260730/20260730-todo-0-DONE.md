# Phase 2 — ModuleHeader

## Objective

Implement the fully working `ModuleHeader` standalone component that the Shell injects above each MFE module.

At the end of this phase the component must:

- Match the approved inputs / outputs API
- Implement the three-section layout (status | title | actions)
- Reflect collapsed / size / fullscreen visual rules
- Use only design tokens from the theme
- Be exported from the public API
- Include JSDoc and basic documentation

## Important constraints

- Desktop-only.
- **No drag handle and no `dragStart` output.** Drag contracts live in `@cobranza-apps/mfe-events` and the Shell.
- Title is **never** editable from the header.
- When `isFullscreen === true`, render **only** the title (no status icon section, no action buttons).
- Prefer Font Awesome Free icons via `@fortawesome/angular-fontawesome`. May use another lib if required.
- All colors, spacing, radii and focus styles must come from `--cba-*` tokens.
- Component must be **standalone**.

## API (must match exactly)

### Inputs

| Name | Type | Default | Description |
| ------ | ------ | --------- | ------------- |
| `title` | `string` | `No default value. Make it always required.` | Module title (provided by the MFE / Shell) |
| `size` | `'50%' \| '100%'` | `'100%'` | Current width mode |
| `isCollapsed` | `boolean` | `false` | Whether the module body is collapsed |
| `isFullscreen` | `boolean` | `false` | Whether the module is shown in fullscreen view |
| `status` | `'loading' \| 'loaded' \| 'success' \| 'warning' \| 'error' \| 'dirty' \| null` | `null` | Optional status indicator |

### Outputs

| Name | Payload | Description |
| ------ | --------- | ------------- |
| `collapseToggle` | `void` | User clicked collapse / expand |
| `sizeToggle` | `'50%' \| '100%'` | User requested the **target** size |
| `remove` | `void` | User requested to remove the module |
| `fullscreenToggle` | `void` | User requested fullscreen |

### Status semantics

| Value | Visual | Typical use |
| ------- | -------- | ------------- |
| `loading` | Spinner | Data loading / ongoing operation |
| `loaded` | Check | Data ready (no explicit save) |
| `success` | Stronger success check | Explicit save / submit succeeded |
| `warning` | Warning triangle | Soft validation / incomplete data |
| `error` | Error / times | Load failure or hard validation error |
| `dirty` | Subtle pencil or dot | Unsaved changes present |
| `null` | Nothing | Normal state |

Note: all icons must show clear meaning on mouse on-hover it.

### 2. Template structure (three sections) [DONE]

Implement this layout:

```
┌──────────────────────────────────────────────────────────────┐
│ [status]   Title text that can grow in height          [btns] │
└──────────────────────────────────────────────────────────────┘
```

- [x] **Left — status section**
  - Fixed width, top-aligned.
  - Rendered only when `status` is not `null`.
  - Contains the status icon only (no extra text required in Phase 2).

- [x] **Center — title section**
  - `flex: 1` (takes remaining horizontal space).
  - Title text must remain fully visible; the header may grow in height when the title is long.
  - Use `var(--cba-text-primary)` and calm typography.

- [x] **Right — actions section**
  - Fixed width, always top-right aligned.
  - Contains the control buttons (see below).
  - Hidden entirely when `isFullscreen === true`.

When `isFullscreen === true`:

- [x] Render **only** the title (no status section, no action buttons).

### 4. Action buttons (visible only when not fullscreen) [DONE]

Implement four controls:

1. **Collapse / Expand**
   - When `isCollapsed === false` → show collapse icon; click emits `collapseToggle`.
   - When `isCollapsed === true` → show expand icon; click emits `collapseToggle`.
   - Other buttons stay visible.

2. **Size toggle**
   - When `size === '100%'` → button represents “go to 50%”; click emits `sizeToggle` with `'50%'`.
   - When `size === '50%'` → button represents “go to 100%”; click emits `sizeToggle` with `'100%'`.
   - Other buttons stay visible.

3. **Remove**
   - Click emits `remove`.

4. **Fullscreen**
   - Click emits `fullscreenToggle`.

- [x] Use icon-only buttons with clear `aria-label`s (and optionally `title` tooltips).
- [x] Buttons must be keyboard operable (native `<button>` elements).
- [x] Hover / active / focus states use `--cba-hover`, `--cba-active` and `--cba-focus-ring` (or the `cba-focus-ring` mixin).
- [x] Disabled styles are not required unless a future input needs them.

### 5. Visual behaviour rules (recap) [DONE]

- [x] **Collapsed:** only the collapse button icon changes to expand; everything else remains.

- [x] Minimum height ≈ `var(--cba-module-header-min-height)` (40px). Header may grow taller for long titles; title can be show in multi lines.
- [x] No border/shadow ownership here (that belongs to `ModuleContainer`).

## Explicitly out of scope for Phase 2

- Drag handle / `dragStart`
- Editable title
- Module body / scroll behaviour (belongs to `ModuleContainer`)
- Shell header / footer behaviour
- Any other components (`CbaButton` may be used internally later, but is not required in this phase; native buttons + icons are fine)
