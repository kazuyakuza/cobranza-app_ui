# Phase 3 — ModuleContainer

## Objective

Implement the fully working `ModuleContainer` standalone component that wraps each MFE module: it hosts the header area and the module body, applies size / collapse / fullscreen behaviour, and provides consistent chrome (border, shadow, padding, scroll).

At the end of this phase the component must:

- Match the approved inputs API
- Apply width mode (50% / 100%)
- Hide or collapse the body when `isCollapsed`
- Apply border-radius + shadow **only when not fullscreen**
- Provide internal scroll when expanded
- Support configurable padding
- Use only design tokens from the theme
- Be exported from the public API
- Include JSDoc and basic documentation

## Important constraints

- Desktop-only.
- Scroll exists **only** while the module is expanded. Outside this container the Shell workspace handles scrolling.
- Border-radius and shadow are applied **only when `isFullscreen === false`**.
- Prefer content projection for the header and the body (do not hard-wire a specific header component inside the container if projection is cleaner).
- All colors, spacing, radii, shadows and focus styles must come from `--cba-*` tokens.
- Component must be **standalone**.
- Do not implement drag-and-drop, workspace state, or routing.

## API (must match exactly)

### Inputs

| Name | Type | Default | Description |
| ------ | ------ | --------- | ------------- |
| `size` | `'50%' \| '100%'` | `'100%'` | Width mode of the module |
| `isCollapsed` | `boolean` | `false` | When true, the module body is hidden / collapsed |
| `isFullscreen` | `boolean` | `false` | Fullscreen mode (no border/shadow chrome) |
| `padding` | `'none' \| 'sm' \| 'md'` | `'sm'` | Internal padding of the body area |

### Content projection

Recommended slots:

- **Header slot** — projects the module header (typically `cba-module-header`).
- **Default / body slot** — projects the MFE content.

Exact projection API (attribute selectors vs nested elements) may be chosen by the implementer as long as it is clear, documented, and ergonomic for the Shell.

  - Selector: `cba-module-container`
  - Style: SCSS, ViewEncapsulation default (emulated) unless there is a strong reason otherwise
  - Change detection: prefer `OnPush` if it fits cleanly with the inputs

- [x] Declare all inputs listed above.
- [x] Add complete JSDoc on the component class and every public `@Input()`. Must be especially useful for AI agents.

### 2. Template structure [DONE]

Implement a clear structure, for example:

```
┌─────────────────────────────────────────┐
│  [projected header / ModuleHeader]      │
├─────────────────────────────────────────┤
│                                         │
│  [projected body / MFE content]         │
│  (scrollable when expanded)             │
│                                         │
└─────────────────────────────────────────┘
```

- [x] Project the header (top).
- [x] Project the body (below the header).
- [x] When `isCollapsed === true`, the body must not be visible (and must not occupy layout space for scrolling). Preferred approach: hide/remove the body region entirely while collapsed.
- [x] When `isFullscreen === true`, the container should still host header + body, but **without** the module chrome (no border-radius, no module shadow).

### 3. Size behaviour

- [ ] When `size === '100%'` → container takes full available width of its parent row/cell.
- [ ] When `size === '50%'` → container takes half of the available width (or the class/style equivalent that the Shell layout expects).
- [ ] Apply size via CSS classes or host bindings that the Shell can rely on. Keep the mapping simple and documented.

### 4. Chrome (border, radius, shadow)

- [ ] When `isFullscreen === false`:
  - Apply border using a subtle border token (`--cba-border-subtle` or `--cba-border-default`)
  - Apply `border-radius` using `--cba-radius-md` (or equivalent)
  - Apply `box-shadow: var(--cba-shadow-module)`
  - Background should use an elevated / secondary surface token as appropriate (`--cba-bg-secondary` or `--cba-bg-elevated`)
- [ ] When `isFullscreen === true`:
  - Do **not** apply module border-radius / module shadow
  - Let the Shell fullscreen view own the outer chrome

### 5. Padding

- [ ] Map the `padding` input to spacing tokens:

  | Value | Suggested padding |
  | ------- | ------------------- |
  | `none` | `0` |
  | `sm` | `var(--cba-space-2)` or `var(--cba-space-3)` (small, balanced) |
  | `md` | `var(--cba-space-4)` or `var(--cba-space-5)` |

- [ ] Padding applies to the **body** region (not necessarily to the header).
- [ ] Default remains `sm`.

### 6. Scroll behaviour

- [ ] When expanded (`isCollapsed === false`), the body region is the scroll container.
- [ ] When collapsed, there is no active body scroll area.
- [ ] Preferred scrollbar styling (CSS-only is enough for this phase):
  - Thin by default
  - Larger thumb on hover if reasonably achievable with pure CSS
  - Optional top/bottom jump buttons are **nice-to-have**, not required for acceptance
- [ ] Do not capture scroll outside the module body; the Shell workspace scrolls independently.

### 7. Integration with ModuleHeader

- [ ] The container must work cleanly when the projected header is `cba-module-header`.
- [ ] Do not re-implement header controls inside the container.
- [ ] Collapsed / fullscreen / size state is driven by inputs; the container reacts visually, it does not own the source of truth (Shell does).

### 8. Styles

- [ ] Component SCSS uses only CSS variables / theme mixins.
- [ ] Layout should be robust for long content and long titles (header may grow; body scrolls).
- [ ] Keep spacing balanced.
- [ ] Interactive / focus concerns mainly live in the header buttons; the container itself should not introduce noisy visuals.

### 9. Export

- [ ] Export `ModuleContainerComponent` from `src/public-api.ts`.
- [ ] Ensure the library builds successfully with the new component.

### 10. Documentation & tests for this phase

- [ ] JSDoc on every public member (already required above).
- [ ] Add a short section to the library docs (new file under `/docs`, linked from `README.md` and related docs) covering:
  - Selector and basic usage example (with projected `cba-module-header` + body content)
  - Full inputs table
  - Size / collapsed / fullscreen behaviour
  - Padding options
  - Note that scroll is internal to the body when expanded
  - Note that border/shadow are suppressed in fullscreen
- [ ] Add focused unit tests only where they add real value, for example:
  - Applies the correct size class / host state for `50%` and `100%`
  - Hides body when `isCollapsed` is true
  - Does not apply module shadow/border chrome when `isFullscreen` is true
  - Applies the expected padding class for `none` / `sm` / `md`  
  Keep the test suite small; prefer clarity over exhaustive coverage.

## Acceptance criteria

Phase 3 is complete when all of the following are true:

| # | Criterion |
| --- | ----------- |
| 1 | `cba-module-container` standalone component exists and compiles. |
| 2 | All inputs match the API table above. |
| 3 | Header and body can be projected cleanly. |
| 4 | `size` switches between 50% and 100% layout behaviour. |
| 5 | Body is hidden / non-scrollable when `isCollapsed` is true. |
| 6 | Border-radius + module shadow apply only when not fullscreen. |
| 7 | Body is the internal scroll container when expanded. |
| 8 | `padding` input controls body padding with token-based values. |
| 9 | Styles use only theme tokens. |
| 10 | Component is exported from `public-api.ts`. |
| 11 | Library build succeeds. |
| 12 | Basic usage documentation and minimal unit tests are present. |

## Explicitly out of scope for Phase 3

- Drag-and-drop
- Workspace row management / persistence
- Shell routing into fullscreen views
- Re-implementing ModuleHeader controls
- Top/bottom scrollbar jump buttons (optional only)
- Any other presentational components (`CbaButton`, `CbaCard`, etc.)
