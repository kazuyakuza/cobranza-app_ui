# Phase 6 — Dropdown, Popover, Typeahead & ModuleFooter

## Objective

Add the remaining high-value overlay / discovery controls and an optional module footer:

- `CbaDropdown` — thin wrapper on ng-bootstrap dropdown
- `CbaPopover` — thin wrapper on ng-bootstrap popover
- `CbaTypeahead` — thin wrapper on ng-bootstrap typeahead (`NgbTypeahead`)
- `CbaModuleFooter` — optional plain module footer that can show status text aligned with `ModuleHeader` status

At the end of this phase Shell and MFEs should be able to use these controls with consistent gray-theme styling without each MFE restyling Bootstrap primitives ad hoc.

## Important constraints

- Desktop-only.
- **Bootstrap / ng-bootstrap are the base.** Do not reimplement dropdown, popover, or typeahead behaviour from scratch.
- Wrappers stay thin: stable `cba-*` API + theme chrome + projection/slots.
- No business logic, no BFF calls, no validation framework.
- All visuals use `--cba-*` tokens.
- Components must be standalone.
- APIs must be clear for AI agents (JSDoc + docs examples).

## Tasks

### 1. Implement CbaDropdown [DONE]

**Selector:** `cba-dropdown`  
**Base:** `@ng-bootstrap/ng-bootstrap` dropdown

ng-bootstrap owns open/close, keyboard behaviour and menu positioning. `CbaDropdown` owns theme styling and a stable consumer API.

#### API (suggested)

| Kind | Name | Notes |
| ------ | ------ | ------- |
| Content | toggle | Projected toggle (usually a `cba-button` or icon button) |
| Content | menu items | Projected dropdown items / menu content |
| Input | `placement` | Optional placement if thin to expose |
| Input | `disabled` | Optional disabled state for the toggle side |

Keep the API small. Prefer projection over a complex item config model.

#### Behaviour & visuals

- [x] Build on ng-bootstrap dropdown — do not invent a custom menu system.
- [x] Menu surface uses elevated background + subtle border + radius tokens.
- [x] Item hover/active states use `--cba-hover` / `--cba-active`.
- [x] Text uses primary/secondary tokens with calm contrast.
- [x] Works naturally with `cba-button` as toggle.
- [x] Place under `src/lib/components/dropdown/`.
- [x] Export from `src/public-api.ts`.
- [x] Build must succeed.

#### Docs & tests

- [x] JSDoc + example with button toggle and a few menu items.
- [x] Explicit note that behaviour comes from ng-bootstrap.
- [x] Minimal tests for wrapper concerns only (projection / class mapping), not ng-bootstrap internals.

### 2. Implement CbaPopover [DONE]

**Base:** `@ng-bootstrap/ng-bootstrap` popover

#### API (suggested)

| Kind | Name | Notes |

| Input | `placement` | e.g. top/bottom/left/right if exposed thinly |
| Input | `triggers` | Optional; default should support hover and/or click as documented |

Choose the ergonomics that stay closest to ng-bootstrap while still giving a stable `cba-*` usage pattern.

#### Behaviour & visuals

- [x] Surface uses elevated background, subtle border, radius tokens.
- [x] Title/body typography aligned with theme text tokens.
- [x] Keep animation/positioning delegated to ng-bootstrap.
- [x] Place under `src/lib/components/popover/`.
- [x] Export from `src/public-api.ts`.
- [x] Build must succeed.

#### Docs & tests

- [x] JSDoc + example (including a Shell-footer-like hover usage if possible).
- [x] Explicit note that behaviour comes from ng-bootstrap.
- [x] Minimal wrapper tests only.

### 3. Implement CbaTypeahead

**Selector:** `cba-typeahead`  
**Base:** `@ng-bootstrap/ng-bootstrap` typeahead (`NgbTypeahead`)

This is the “user types → dropdown of options appears below” control.  
**Do not introduce a separate autocomplete library.** Use ng-bootstrap typeahead as the engine.

#### API (suggested)

| Kind | Name | Notes |
| ------ | ------ | ------- |
| Input | `label` | Visible label (reuse form-field conventions from Phase 5) |
| Input | `placeholder` | Optional |
| Input | `disabled` | Disabled state |
| Input | `hint` | Optional helper text |
| Input | `error` | Optional visual error text |
| Input | `search` / items source | Thin binding to ng-bootstrap search function or documented equivalent |
| Input | `resultFormatter` / display helper | Optional thin pass-through if useful |
| Control value | forms compatibility | Prefer Angular forms-friendly binding if feasible |

Exact input names may follow ng-bootstrap closely to stay thin; document them clearly.

#### Behaviour & visuals

- [ ] Reuse the shared form-field structure (label / control / hint / error) from Phase 5.
- [ ] Rely on ng-bootstrap for filtering popup, keyboard navigation and selection behaviour.
- [ ] Theme the input surface like `cba-input`.
- [ ] Theme the suggestions dropdown like elevated menu surface (same language as dropdown).
- [ ] No async BFF logic inside the component — consumer provides the search function / data path.
- [ ] Place under `src/lib/components/typeahead/`.
- [ ] Export from `src/public-api.ts`.
- [ ] Build must succeed.

#### Docs & tests

- [ ] JSDoc + example with a simple local search function.
- [ ] Explicit note: engine is ng-bootstrap typeahead; no extra autocomplete dependency.
- [ ] Minimal tests for field rendering / disabled / error visibility; do not re-test typeahead matching internals.

### 4. Implement CbaModuleFooter (optional module footer)

**Selector:** `cba-module-footer`

Optional footer region for a module. Initial version is intentionally **plain**.

#### Goals for v1

- Finite height footer bar
- Background color only (theme surface token)
- Can show **module status text** that matches the semantic meaning of `ModuleHeader` status icons
- No complex toolbar, no extra actions required in this phase

#### API (suggested)

| Kind | Name | Type / values | Default | Notes |
| ------ | ------ | --------------- | --------- | ------- |
| Input | `status` | `'loading' \| 'loaded' \| 'success' \| 'warning' \| 'error' \| 'dirty' \| null` | `null` | Align with ModuleHeader status values |
| Input | `statusText` | `string` | optional | Explicit text override |
| Content | default | projected content | — | Optional extra plain content if needed |

Status text mapping when `statusText` is not provided (suggested defaults):

| Status | Default text |
| -------- | ---------------- |
| `loading` | Loading… |
| `loaded` | Ready |
| `success` | Saved |
| `warning` | Attention needed |
| `error` | Error |
| `dirty` | Unsaved changes |
| `null` | No status text |

Implementer may refine the copy, but semantics must stay aligned with header status icons.

#### Behaviour & visuals

- [ ] Plain bar: background from theme (`--cba-bg-secondary` or `--cba-bg-tertiary`), finite height, balanced horizontal padding.
- [ ] No heavy borders/shadows required in v1 (keep it calm and secondary to the header).
- [ ] Status text uses muted/secondary or accent-tinted color according to status.
- [ ] Optional: small status icon mirrored from header semantics; text is the priority in v1.
- [ ] Designed to sit under module body content, typically inside / below `ModuleContainer` body area as the Shell/MFE decides.
- [ ] Do **not** make the footer mandatory. Modules can omit it.
- [ ] Place under `src/lib/components/module-footer/`.
- [ ] Export from `src/public-api.ts`.
- [ ] Build must succeed.

#### Docs & tests

- [ ] JSDoc + example showing footer with `status="dirty"` and default text.
- [ ] Document relationship with `ModuleHeader` status values.
- [ ] Minimal tests: renders default text per status; `statusText` override wins; renders nothing status-related when `status` is null and no content is projected.

#### Integration note

- `ModuleContainer` does **not** need to hard-require this footer.
- Consumers may project it at the bottom of the module body or compose it next to container content.
- If a tiny optional slot in `ModuleContainer` makes composition clearly better, it may be added — but keep it optional and non-breaking.

## Acceptance criteria

Phase 6 is complete when all of the following are true:

| # | Criterion |
| --- | ----------- |
| 1 | `CbaDropdown` exists as a thin ng-bootstrap dropdown wrapper and compiles. |
| 2 | `CbaPopover` exists as a thin ng-bootstrap popover wrapper and compiles. |
| 3 | `CbaTypeahead` exists as a thin ng-bootstrap typeahead wrapper and compiles. |
| 4 | `CbaModuleFooter` exists with plain background + status text aligned to header status values. |
| 5 | No custom dropdown/popover/typeahead engines were introduced. |
| 6 | Visuals use only theme tokens. |
| 7 | All new components are exported from `public-api.ts`. |
| 8 | Library build succeeds. |
| 9 | Docs + minimal tests for this phase are present. |

## Explicitly out of scope for Phase 6

- Accordion (later, when a real MFE need appears)
- Bootstrap placeholders (use `CbaSkeleton` instead)
- Complex footer toolbars / action clusters
- Toast/notification system
- Advanced select/typeahead features (multi-select, tagging, virtual scroll)
- Public API final polish / package delivery cleanup → **Phase 7**
