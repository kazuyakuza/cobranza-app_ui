# Phase 0 — Project Bootstrap & Library Scaffolding

## Objective

Turn the current base project into a clean, buildable **Angular 22 library** named `@cobranza-apps/ui`, ready to receive the theme and components in later phases.

At the end of this phase the library must:

- Build successfully
- Have the correct package name and peer dependencies
- Expose a clean (empty / minimal) public API
- Have the theme folder structure prepared (files only, no tokens yet)
- Be ready for SCSS theme work in Phase 1

**No UI components and no design tokens are implemented in this phase.**

## Important constraints

- **Not a monorepo.** There is no separate application host + library. The whole repository is the library itself.
- Prefer the standard Angular library layout intended for a publishable package (`ng-packagr`).
- Do not invent features outside the project brief.
- Tests and documentation for this phase are created only for what this phase actually delivers.
- Prefer small, focused commits.

## Tasks

### 1. Establish Angular 22 library project

- [ ] If the base project is **not** yet a proper Angular library targeting Angular 22, convert or recreate it as one.
- [ ] Final shape must be a **publishable library** (ng-packagr style), not a full application.
- [ ] Use **standalone** components by default. Do **not** generate or keep NgModules.
- [ ] Library selector prefix: `cba` (future selectors will be `cba-module-header`, `cba-button`, etc.).

Reference approach (adapt to what already exists; do not destroy git history!):

```bash
# Only if starting from a nearly empty folder
ng new ui --create-application=false --style=scss --routing=false --ssr=false
cd ui
ng generate library ui --prefix=cba --standalone
```

If Angular files already exist, align `package.json`, `tsconfig`, `ng-package.json` and source layout to Angular 22 library standards instead of running a full `ng new`.

### 2. Review Peer dependencies

Configure the library `package.json` (the one that ships with the built package) with these peer dependencies:

```json
{
  "peerDependencies": {
    "@angular/common": "^22.0.0",
    "@angular/core": "^22.0.0",
    "@angular/forms": "^22.0.0",
    "bootstrap": "^5.3.0",
    "@ng-bootstrap/ng-bootstrap": "^21.0.0",
    "@fortawesome/angular-fontawesome": "^5.0.0",
    "@fortawesome/fontawesome-svg-core": "^6.0.0 || ^7.0.0",
    "@fortawesome/free-solid-svg-icons": "^6.0.0 || ^7.0.0",
    "@fortawesome/free-regular-svg-icons": "^6.0.0 || ^7.0.0"
  }
}
```

Adjust exact minimum patch versions to the latest compatible releases available at implementation time, but stay on:

- Angular **22.x**
- ng-bootstrap line that supports Angular 22 (currently 21.x)

Also install the same packages as `devDependencies` (and/or dependencies where required) so the library can be built and developed inside this repository.

### 3. Install dependencies (if not already)

- [ ] Install Bootstrap 5.
- [ ] Install `@ng-bootstrap/ng-bootstrap` (Angular 22 compatible version).
- [ ] Install Font Awesome packages:
  - `@fortawesome/angular-fontawesome`
  - `@fortawesome/fontawesome-svg-core`
  - `@fortawesome/free-solid-svg-icons`
  - `@fortawesome/free-regular-svg-icons`
- [ ] Update the lockfile.
- [ ] Confirm `package.json` and lockfile are consistent.

### 4. SCSS support and theme folder skeleton

- [ ] Confirm the library uses **SCSS** (`.scss` files).
- [ ] Ensure the build can process SCSS (needed for the theme in Phase 1).
- [ ] Create the theme folder structure with placeholder files only:

```
src/lib/theme/
├── _variables.scss      # placeholder – tokens come in Phase 1
├── _utilities.scss      # placeholder
├── _mixins.scss         # placeholder
└── theme.scss           # imports the partials (even if empty)
```

Example minimal `theme.scss`:

```scss
@use 'variables';
@use 'utilities';
@use 'mixins';
```

Do **not** implement design tokens or utility classes yet.

### 5. Public API entry point

- [ ] Locate or create the library entry file (usually `src/public-api.ts`).
- [ ] Keep it minimal for Phase 0. Example:

```ts
/*
 * Public API Surface of @cobranza-apps/ui
 *
 * Components, directives and theme helpers will be exported in later phases.
 */
```

- [ ] Remove any default demo / placeholder component that the CLI generated and that is not part of the final library.
- [ ] Ensure nothing unwanted is exported.

### 6. Path mapping

- [ ] Configure TypeScript paths so local development can import from `@cobranza-apps/ui` (pointing at the library source or its public-api).
- [ ] Because this repo *is* the library, a simple path to `src/public-api.ts` is enough for now.

### 7. Clean-up & Build verification

- [ ] Delete unused CLI-generated files if any (demo components, leftover NgModules, irrelevant boilerplate).
- [ ] Run the library build:

```bash
ng build ui
# or the npm/yarn/pnpm script defined in package.json
```

- [ ] Confirm the build finishes with **no errors**.
- [ ] Inspect the output (`dist/` or equivalent) and verify package name and entry points look correct.

## Explicitly out of scope for Phase 0

- Design tokens and full theme → **Phase 1**
- Any UI component (`ModuleHeader`, `CbaButton`, etc.) → later phases
- Storybook
- npm publish configuration / CI publishing
- Drag-and-drop, workspace state, business logic
- Mobile / responsive styles
- Secondary entry points
