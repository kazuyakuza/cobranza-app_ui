# Phase 1 — Theme Foundation

## Objective

Implement the complete intermediate gray design system:

- All CSS custom properties (`--cba-*`)
- Utility classes
- Optional SCSS mixins
- Base typography and sensible defaults
- Theme entry point that consumers (Shell and MFEs) can import

No UI components are built in this phase.

## Important constraints

- Desktop-only. Do not add mobile breakpoints.
- Prefer CSS variables over hard-coded colors everywhere.
- Theme must be consumable via SCSS import.
- Prefer encapsulation; avoid forcing global styles unless strictly necessary for the tokens themselves (`:root`).
- Keep the visual language modern, professional, calm and friendly (not rigid corporate).
- Spacing should feel balanced — neither sparse nor cramped.

### 5. Base typography & defaults

- [ ] In `theme.scss` (or a dedicated `_base.scss` imported by it) define:

  - Font stack: Inter first, then system-ui / system fallbacks
  - Base font-size: `14px`
  - Base line-height: `1.5`
  - Default text color: `var(--cba-text-primary)`
  - Default background: `var(--cba-bg-primary)` (only if it makes sense for the library’s global entry; otherwise leave background to the consumer)
  - Heading weights: 500–600
  - Sensible defaults for links and focusable elements that use `--cba-focus-ring`

- [ ] Do not fight Bootstrap aggressively. Prefer complementary defaults that work well when Bootstrap 5 CSS is also loaded by the consumer.

### 6. Make the theme consumable

- [ ] Ensure the theme SCSS is part of the library build output (ng-packagr assets / styles configuration, or documented path that consumers can import).
- [ ] Document (in README or a short theme section) how a consumer imports the theme, for example:

```scss

@use '@cobranza-apps/ui/theme';
// or the concrete path exposed by the built package
```

- [ ] Prefer that the CSS variables are available globally once the theme file is loaded (`:root`), while utility classes remain opt-in.

## Acceptance criteria

Phase 1 is complete when all of the following are true:

| # | Criterion |
| --- | ----------- |
| 1 | `_variables.scss` contains every token listed in the project brief with the correct values. |
| 2 | `_utilities.scss` provides the background, text, border, radius and shadow utilities. |
| 3 | `_mixins.scss` contains at least the focus-ring and elevated-surface mixins. |
| 4 | `theme.scss` imports the partials and compiles without errors. |
| 5 | Base typography (Inter / system-ui, 14px, 1.5) is defined. |
| 6 | Library build succeeds. |

## Explicitly out of scope for Phase 1

- Any Angular component (`ModuleHeader`, `CbaButton`, etc.)
- Custom scrollbar styling for modules (belongs with `ModuleContainer`)
- Dark/light theme switching (single intermediate gray theme only)
- Mobile breakpoints
- Secondary package entry points beyond what is needed to import the theme
