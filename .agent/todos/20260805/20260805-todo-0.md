# Phase 9 — Surface Hierarchy Fix + Consumer Guide

**Library:** `@cobranza-apps/ui`  
**Depends on:** Phase 8 (Minimal Yet Warm tokens already in `src/theme/_variables.scss`)  
**Trigger:** Shell screenshot (`.agent\screenshots\20260805T161948.png`) still looks flat — modules barely separate from workspace; borders and chrome disappear into cream.

## Diagnosis (from current tokens + Shell screenshot)

Current token values (lib):

| Token | Value | Issue |
| ------- | ------- | -------- |
| `--cba-bg-primary` (canvas) | `#EAE7DC` | OK as warm base |
| `--cba-bg-secondary` (panel) | `#F3F1E9` | **Too close** to canvas (~same band) |
| `--cba-bg-elevated` | `#FCFBF6` | Only a hair lighter than panel |
| `--cba-bg-tertiary` (inset) | `#D8C3A5` | Good contrast, but often **not used** by consumers for table headers |
| `--cba-border-subtle` | `#E7E5DE` | **Nearly invisible** on cream/canvas |
| `--cba-shadow-module` | `0 4px 16px rgba(43,34,28,0.12)` | Soft; may need slightly more presence |

Component wiring in the lib is largely correct:

- `ModuleContainer` (non-fullscreen): `bg-secondary` + `border-subtle` + `shadow-module`
- `ModuleHeader`: `bg-elevated` + `border-bottom: border-subtle`

So the flat look is mainly:

1. **Insufficient luminance gap** between canvas → panel → elevated  
2. **Borders too weak** on warm light surfaces  
3. **Missing consumer guidance** — Shell/MFEs may not apply canvas / inset / strong borders where hierarchy depends on them (workspace bg, table thead, footer pills)

This phase fixes tokens + module chrome in the lib, and publishes a clear consumer guide.

## Objective

1. Make `Minimal Yet Warm` **visibly layered** in the running Shell (without changing theme family).  
2. Ensure module chrome (container + header) reads as cards on the workspace.  
3. Publish **`docs/CONSUMER_GUIDE.md`** so Shell and MFE authors must apply surfaces correctly.

No new components. Token **names** stay stable.

## Important constraints

- Stay in **Minimal Yet Warm** (warm sand/cream/taupe + controlled coral).
- Do **not** rename `--cba-*` tokens.
- Coral remains accent-only (warning/danger/focus), not large fills / primary CTA fills (primary CTA stays warm taupe unless docs say otherwise).
- Desktop-only.
- Agent may tune exact hex/mixes; acceptance is visual hierarchy, not a fixed hex table.

### 6. Write consumer guide [DONE]

Modify related docs and/or create new `docs/CONSUMER_GUIDE.md`.

Write down a clear guide aimed at **Shell and MFE developers** (and AI agents). Must include:

#### 6.1 Theme load (once)

- Shell **must** import theme globally:

```scss
@use '@cobranza-apps/ui/theme';
```

- MFEs should rely on Shell-loaded tokens when hosted; if an MFE runs standalone (dev), it must import the same theme once.
- Do not re-declare competing `:root` colors in Shell/MFE.

#### 6.2 Surface ownership map

| UI region | Token | Who applies it |
| ----------- | -------- | ---------------- |
| Shell workspace / workbench background | `--cba-bg-primary` | **Shell** |
| Shell header / footer chrome | `--cba-bg-elevated` (or documented Shell choice) | **Shell** |
| Module card surface | `--cba-bg-secondary` via `cba-module-container` | **Lib** (ModuleContainer) |
| Module header band | `--cba-bg-elevated` via `cba-module-header` | **Lib** (ModuleHeader) |
| Table header / recessed wells | `--cba-bg-tertiary` | **MFE** (or shared table styles) |
| Dropdown / popover / modal surfaces | elevated tokens via wrappers | **Lib** components |
| Footer section pills | border-strong + panel/elevated | **Shell** |

#### 6.3 Shell checklist

- [ ] Workbench/workspace element uses `background: var(--cba-bg-primary)` (not raw `#fff` / Bootstrap gray).
- [ ] Modules are wrapped with `cba-module-container` (so border + shadow + panel bg apply).
- [ ] Module headers use `cba-module-header` (not a custom bar that ignores elevated).
- [ ] No global CSS that sets `background: #fff` on `.card`, `main`, or module wrappers.
- [ ] Footer pills use visible border (`--cba-border-strong` or default) against canvas.
- [ ] Avoid painting the entire shell with `--cba-bg-secondary` (kills canvas/module contrast).

#### 6.4 MFE checklist

- [ ] Prefer lib components (`cba-button`, `cba-card`, form wrappers) over unthemed Bootstrap.
- [ ] Tables: thead/th use `--cba-bg-tertiary` + `--cba-text-secondary` (muted is restricted on inset).
- [ ] Do not hard-code hex; use `var(--cba-*)` or `.cba-*` utilities.
- [ ] Do not import a second design system that overrides `:root`.

#### 6.5 Anti-patterns

- Same background on workspace and module body.
- Using only `--cba-border-subtle` for important chrome on cream.
- Large coral backgrounds.
- Hard-coded colors that fight tokens.
- Expecting ModuleContainer to style the Shell workspace (it only styles the module card).
