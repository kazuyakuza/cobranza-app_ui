# Phase 12 — Host encapsulation audit + Angular demo app

Library: `@cobranza-apps/ui`  
Depends on: Components already implemented; theme tokens stable  

Trigger (confirmed in Shell runtime HTML):  
`CbaButton` variant classes live on the host (`_nghost-*`), but component SCSS was written as descendant selectors (`.cba-button--primary .cba-button__control`). Under Angular emulated encapsulation those become `.cba-button--primary[_ngcontent-*] …`, which never match the host. Primary (and likely other variants) therefore do not apply in the Shell even though markup and CSS are both present.

The static `docs/theme-preview.html` & `docs/theme-preview.css` is DEMO CSS ONLY and cannot catch this class of bug.

## Objectives

1. Audit and fix host-modifier encapsulation across the entire library so Shell-rendered components match intended styles.
2. Replace the static HTML theme preview with a real Angular demo mini-app that consumes the library build (same path as Shell).
3. Ship the demo app build as the canonical visual example of the theme + components (included in the library packaging / publish artifacts as documented).
4. Remove static preview files once the demo app covers the same content.

## Important constraints

- Desktop-only.
- Do not switch the library to `ViewEncapsulation.None` as a blanket fix.
- Prefer `:host(.modifier)` / `:host-context` where modifiers are on the host; keep emulated encapsulation.
- Demo app must depend on the built library (path mapping to `dist` or workspace package), not on deep `src/` imports that bypass packaging.
- Minimal Yet Warm remains the theme; demo shows real tokens via `@use '@cobranza-apps/ui/theme'` (or published subpath).
- Spanish UI copy rules unchanged for library-owned strings.
- No CDK requirement in the demo beyond what the lib already avoids for drag (optional projected handle can be a static button without DnD).

## Tasks

### Part A — Encapsulation audit & fix

#### A.1 Problem pattern

| Bad (breaks when class is on host) | Good |
|------------------------------------|------|
| `.cba-button--primary .cba-button__control { }` | `:host(.cba-button--primary) .cba-button__control { }` |
| `.cba-module-container--fullscreen { }` on host rules written as non-host selectors | `:host(.cba-module-container--fullscreen) { }` |

#### A.2 Inventory (must check every component)

For each component under `src/components/`:

- [x] [DONE] List classes applied via `host:`, `@HostBinding`, or host `class` bindings (variants, sizes, states, layout flags).
- [x] [DONE] List SCSS selectors that target those modifier classes.
- [x] [DONE] Fix any selector that assumes the modifier is an internal node (`_ngcontent`) when it is actually on the host (`_nghost`).
- [x] [DONE] Re-check `::ng-deep` usage — do not introduce new piercing; fix host selectors instead.

Minimum known hotspots:

| Component | Host modifiers to verify |
| ----------- | --------------------------- |
| `CbaButton` | `--primary`, `--secondary`, `--ghost`, `--danger`, `--success`, `--sm`, `--md`, `--disabled`, `--loading`, `--truncate`, `--icon-only`, `--block` |
| `ModuleContainer` | `--size-50`, `--size-100`, `--fullscreen`, `--padding-*`, `--collapsed` |
| `ModuleHeader` | `--fullscreen` (and any status classes if on host) |
| `ModuleFooter` | status / layout host classes if any |
| `CbaBadge` | variant / solid / outline host classes |
| `CbaCard` | any host layout flags |
| `CbaSkeleton` | variant host classes |
| `CbaEmptyState` | if any |
| Form controls / dropdown / popover / typeahead / accordion / modal | host state classes (`disabled`, `invalid`, etc.) if bound on host |
