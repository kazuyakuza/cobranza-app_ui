### Task 1 — Expose Scroll Chaining Control on Module Container [DONE]

**Problem:** `ModuleContainerComponent` applies `overscroll-behavior: contain` to `.cba-module-container__body`, which traps mouse-wheel events inside the module body and prevents scroll chaining to the parent workspace container. The Shell previously used a `::ng-deep` override to reset it to `auto`, but `::ng-deep` is now prohibited.

**Requested fix:**

- Option A: Remove `overscroll-behavior: contain` from `.cba-module-container__body` entirely.
- Option B: Expose an input (e.g., `[scrollChaining]="true"`) that allows consumers to opt into `overscroll-behavior: auto`.

**Shell workaround:** Removed the `::ng-deep` override. Scroll over modules may be slightly trapped until this library fix is released.

**Reference:** `src/app/workspace/module-host.component.ts` JSDoc "Workspace scroll behavior". Check below:

```md
## Workspace scroll behavior
`ModuleContainerComponent` from `@cobranza-apps/ui` applies `overscroll-behavior: contain`
to `.cba-module-container__body`, which traps mouse-wheel events inside the module body
and prevents scroll chaining to the workspace (`.shell-workspace`).

The Shell previously overrode this with a scoped shadow-piercing CSS rule, but
shadow-piercing selectors are deprecated and prohibited by project rules. That override has been removed. The proper fix requires a
`@cobranza-apps/ui` change: either stop applying `overscroll-behavior: contain`
to the module body or expose an input (e.g., `[scrollChaining]="true"`). The
library API request is tracked in the UI lib TODO; the workspace scroll will be
restored once the new library version is published.
```

### Task 2 — Retain Panel Background in Fullscreen Mode [DONE]

**Problem:** `ModuleContainerComponent` bundles `background-color`, `border`, `border-radius`, and `box-shadow` under a single `:host(:not(.cba-module-container--fullscreen))` selector. When `[isFullscreen]="true"`, ALL of these properties disappear, including the panel background color. The container becomes transparent, showing the workspace canvas color through it.

**Requested fix:**

- Split the selector: keep `background-color: var(--cba-bg-secondary)` in fullscreen mode.
- Only suppress `border`, `border-radius`, and `box-shadow` in fullscreen mode.

**Shell workaround:** Added `.cba-bg-secondary` utility class to `<cba-module-container>` in the fullscreen placeholder component.

**Reference:** `src/app/workspace/module-fullscreen-placeholder.component.ts`.

```ts

  ...
  template: `
    <div class="module-fullscreen" role="region" aria-label="Módulo a pantalla completa">
      <!--
        WORKAROUND: .cba-bg-secondary restores the panel surface color.
        The library removes background-color in fullscreen mode (bundled with
        border/radius/shadow under :host(:not(.cba-module-container--fullscreen))).
        This is a UI library bug; see class JSDoc for details.
      -->
      <cba-module-container [isFullscreen]="true" class="cba-bg-secondary">
        <ng-container [ngComponentOutlet]="stubComponent()" [ngComponentOutletInputs]="stubInputs()" />
      </cba-module-container>
    </div>
  `,
  styles: [`
    /* :host must be block + 100% height so the parent flex container
       constrains it; without this the host stays inline and the child's

      display: block;
      height: 100%;

      height: 100%;
      width: 100%;

      display: flex;
      flex-direction: column;

     * on <cba-module-container> in the template. This is a workaround for a
     * library bug where fullscreen mode removes background-color along with
     * border/radius/shadow. See class JSDoc for full explanation.
     */
    .module-fullscreen cba-module-container {
      flex: 1 1 auto;
      min-height: 0;
    }
  `],
})
```

### Task 3 — Expose Label Truncation on CbaButton [DONE]

**Problem:** `CbaButton` does not expose a way to truncate long labels with ellipsis. The Shell's footer popover has ghost buttons with long labels that overflow. The previous workaround used `::ng-deep` to pierce `.cba-button__label` and apply `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`.

**Requested fix:**

- Option A: Expose a `[truncate]` boolean input on `CbaButton`.
- Option B: Provide a `.cba-text-truncate` utility class that works inside `CbaButton`.

**Shell workaround:** Removed the `::ng-deep` piercing. Labels may overflow until this library fix is released.

### Task 4 — Minimal Square Icon-Only Button [DONE]

**Problem:** The primary plus button (`variant="primary" [icon]="faPlus"`) in the footer popover should be minimal and square-ish (or editable), taking only the space needed for the icon. Currently it may expand due to library default sizing.

**Requested fix:**

- When `CbaButton` has an `[icon]` but no text content, render at minimal square dimensions.
- Ensure the icon is vertically and horizontally centered within the minimal button.
- Should also have minimal padding and/or be configable.

**Shell workaround:** Used `flex: 0 0 auto` on the button's host element, but the library may still apply internal padding or min-width that prevents a true square.

### Task 5 — Block-Level Ghost Button [DONE]

**Problem:** The ghost title button in the footer popover should fill all available width so its label is left-aligned and the container space is fully used. The library's `CbaButton` host may not expand to fill a flex parent.

**Requested fix:**

- Option A: Expose a `[block]` boolean input that makes the button fill its parent width.
- Option B: Ensure the `cba-button` host element naturally fills a flex container when `flex: 1 1 auto` is applied by the consumer.

**Shell workaround:** Applied `flex: 1 1 auto` to the button host, but the library's internal `.cba-button__control` may still shrink to content.

## Shell UI Bug Fixes Round 2 Resume

IMPORTANT: below are ONLY references of external tasks from the shell project (consumer of this UI lib). DO NOT TAKE THEM AS WORK TO DO IN CURRENT PROJECT.

### Task 1 — Remove `::ng-deep` and Fix Workspace Scroll Properly [DONE]

**Problem**: Task 8 (workspace scroll) applied a `::ng-deep` CSS override (`:host ::ng-deep .cba-module-container__body { overscroll-behavior: auto; }`) to work around the library's `overscroll-behavior: contain`. `::ng-deep` is deprecated and prohibited.

### Task 2 — Fix Fullscreen Module Background Color [DONE]

**Problem**: When a module enters fullscreen mode, its background color changes. It should keep the same background color as in workspace mode.

### Task 3 — Fix Drag & Drop: 50% Module Disappears from Workspace Preview [DONE]

**Problem**: When dragging a module from a row that contains exactly 2 modules at 50% width, the dragged module disappears from the workspace preview rows. Only the floating CDK drag preview remains visible. When dragging a different module, the disappeared module reappears at its original position.

### Task 4 — Fix Drag & Drop Preview: No Extra Space on Original Row Hover [DONE]

**Problem**: When dragging a module and the cursor moves over the module's original row, the preview engine adds extra vertical space (gaps/rows) above or below the original row to show where the module could be dropped. This is unnecessary — the module is already in that row.

### Task 5 — Fix Drag & Drop: Move 50% Module to Empty Side of Same Row [DONE]

**Problem**: It is not possible to move a 50% module to the empty side of its own row. The drop target is rejected or the preview doesn't allow it.

### Task 6 — Fix Drag Handle Button Visual Style [DONE]

**Problem**: The drag handle button does not visually match the other header action buttons (collapse, size toggle, remove, fullscreen). By default it has a border and background color. It should look like a plain icon button with the same hover visual effect as the order buttons.

The library provides `.cba-module-header__action` base styling (padding, hover, focus) but the `--drag` modifier is meant to be supplied by the consumer. The Shell does not define any CSS for `.cba-module-header__action--drag`.

### Task 7 — Fix Footer Popover Visual Spacing and Button Sizing [DONE]

**Problem**: The footer popover still has incorrect spacing and button sizing after Task 4. Specific issues:

1. Too much padding
2. Padding between title and plus button
3. Title button should fill available space
4. Plus button should be minimal size
5. Plus button not centered
