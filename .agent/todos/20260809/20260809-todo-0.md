# Phase 11 — ModuleHeader optional drag-handle projection slot [DONE]

**Library:** `@cobranza-apps/ui`  

## Objective

Allow the **Shell** to project an optional drag-handle control into `ModuleHeader`, so `@angular/cdk/drag-drop` (`cdkDragHandle`) can be applied by the Shell without the UI library depending on CDK or owning drag-and-drop behaviour.

At the end of this phase:

- `ModuleHeader` exposes **one optional** content slot for a drag handle
- Slot is empty when the consumer projects nothing (no broken layout)
- Projected control sits in the header actions area with the same visual language as built-in action buttons
- Library still does **not** implement DnD, emit drag events, or require `@angular/cdk`
- Docs describe the Shell integration contract

## Important constraints

- Desktop-only.
- **No** `@angular/cdk` dependency (peer or otherwise) in `@cobranza-apps/ui`.
- **No** `dragStart` / drag outputs on `ModuleHeader`.
- **No** built-in drag handle button rendered by the library when the slot is empty.
- Drag-and-drop remains owned by the **Shell** (and contracts in `@cobranza-apps/mfe-events` if applicable).
- Existing inputs/outputs of `ModuleHeader` stay unchanged.
- When `isFullscreen === true`, header still shows **title only** (no status, no action buttons). The drag-handle slot must **not** appear in fullscreen either (same rule as other actions).
- Spanish aria/copy rules unchanged for library-owned strings; the projected handle’s accessible name is the **consumer’s** responsibility.

## API / contract

### Projection slot

| Selector attribute | Required | Placement | Notes |
|--------------------|----------|-----------|--------|
| `cbaModuleDragHandle` | No | Actions section of the header (with built-in action buttons) | Attribute marker on the projected root element |

**Consumer example (Shell):**

```html
<div cdkDrag>
  <cba-module-container [size]="'100%'">
    <cba-module-header
      [title]="title"
      [status]="status"
      [isCollapsed]="isCollapsed"
      [isFullscreen]="false"
      (collapseToggle)="..."
      (sizeToggle)="..."
      (remove)="..."
      (fullscreenToggle)="..."
    >
      <button
        type="button"
        cbaModuleDragHandle
        cdkDragHandle
        class="cba-module-header__action"
        aria-label="Arrastrar módulo"
      >
        <!-- icon: e.g. Font Awesome grip or hand -->
      </button>
    </cba-module-header>

    <!-- MFE body -->
  </cba-module-container>
</div>
```

Notes for implementers:

- Prefer attribute selector `[cbaModuleDragHandle]` on `<ng-content select="...">`.
- Document that the Shell should put `cdkDrag` on an ancestor that wraps the module (typically outside or on the host the Shell controls), and `cdkDragHandle` on the projected element.
- The library may expose or reuse a public class (e.g. `cba-module-header__action`) so the projected button matches built-in action sizing/hover; do **not** require CDK classes inside the lib.

### Layout order (actions section)

Recommended order when the slot is used:

1. **Projected drag handle** (first / outer edge — conventional for grips)
2. Built-in actions: collapse, size, remove, fullscreen (existing behaviour)

If the current actions order differs, keep existing built-in order and place the drag slot **before** them unless a strong UX reason says otherwise; document the final order.
